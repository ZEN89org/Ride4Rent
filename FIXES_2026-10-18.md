# Ride4Rent fixes — October 18, 2026

## Implemented

- Fixed the 27 TypeScript errors found during the project assessment: missing booking fields, missing theme/style properties, duplicate style keys, incorrect revenue field, and unsupported style references.
- Removed fabricated pickup/return times from booking cards. Actual recorded times are shown when available.
- Moved the toast provider outside authentication/call providers so authentication and calling errors can display correctly.
- Restricted booking actions by participant and current status. Renters cannot approve, reject, start, complete, or mark their own bookings as no-show through the generic status endpoint.
- Added database transactions and renter/vehicle/booking locks to reservation mutations. Failed responses roll back their writes. All availability checks count the same active trip statuses.
- Added capacity, expiry, license, and overlapping-trip checks to payment confirmation. Removed the frontend fallback that retried a failed confirmation through the generic approval endpoint.
- Enforced account suspension on API requests and login. Enforced admin maintenance mode, maximum advance dates, license approval policy, and commission settings. Added a public endpoint for support/settings information.
- Kept license verification separate from payment approval. Administrators verify licenses; confirming a payment no longer grants license approval.
- Made public vehicle prices and booking charges use the same demand-pricing calculation. Fixed static pricing to use `daily_rate`.
- Made review moderation affect public review lists and aggregate ratings.
- Required host receipt confirmation before an extension changes rental dates or totals. Added an operator confirmation button, blocked duplicate submissions, computed extension days from the requested dates, and retained cumulative extension payments for final settlement.
- Validated inspection photos and return mileage. Completing a trip now updates the odometer used by maintenance recommendations.
- Extracted expiration processing into a transaction-safe service and scheduled it every minute. The Docker entrypoint starts the scheduler.
- Moved existing license and business-document files from public to private storage. New uploads use private storage; authorized responses provide 15-minute signed URLs. Direct public document requests are blocked. Private uploads retain database-backed recovery.
- Removed 43 user-upload asset references from the mobile bundle, including licenses, business documents, chat attachments, profile photos, and payment QR images. Only public fleet photos remain in the storage asset allowlist. Build archives exclude user-upload directories.
- Replaced simulated call-audio flags with LiveKit room connection, microphone publication, remote audio subscription, mute, speaker routing, cleanup, and connection-error handling. Removed embedded fallback LiveKit credentials; the server must use its own environment configuration.
- Moved trip tracking from the bookings screen into an app-level provider and native background-location task. Tracking follows active rentals, checks location preferences, stops after completion/logout, and provides a foreground fallback when background tracking is unavailable.
- Connected support contact information to admin settings and replaced the unsupported “message sent” success with an email-composer action.
- Updated the system manual to distinguish manual payment verification, polling/local notifications, and installed-build background tracking.
